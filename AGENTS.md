# 2D Pixel Art Game Character Engine — Agent Rules

## Project Overview
A React + Vite app that uses Gemini AI to generate 2D pixel art game characters and sprite sheet animations. Characters are generated with a green (#00FF00) background, which is then removed via chroma key. Animations are compiled into a sprite sheet for a game engine viewport.

## Architecture
- `src/services/ai.ts` — Gemini API calls for character + animation generation
- `src/lib/imageUtils.ts` — Chroma key background removal
- `src/lib/spriteCompiler.ts` — Extracts frames from AI output, normalizes sizes, compiles sprite sheet
- `src/components/GameViewport.tsx` — Canvas-based game engine with keyboard/touch controls
- `src/App.tsx` — Main UI with 3-step flow: Character → Animations → Engine

## Sprite Sheet Rules (MUST follow)

### Chroma Key Background
- All generated images use **green #00FF00** background
- Prompts require every background pixel to be exactly #00FF00 with no anti-aliasing at character edges
- AI generates clean hard pixel edges between character and background

### Animation Generation Prompts
1. ALL animation strips must be a WIDE horizontal image (4:1+ aspect ratio)
2. Exactly 4 poses in ONE horizontal row — never a grid, never stacked
3. Wide green gaps between poses — poses must never touch
4. ALL frames must face the SAME direction as the reference character — no flipping, no mirroring, no rotation
5. Frame 4 must face the same way as Frame 1
6. Character proportions, pixel scale, outfit, and colors must be identical to reference in every frame
7. Background must be solid flat #00FF00 green — no gradients, no shadows, no anti-aliasing at edges

### Character Facing Direction (ALL perspectives)
- Characters MUST always face to the RIGHT side of the image by default
- This applies to ALL perspectives: platformer, isometric, and top-down
- Isometric: character body angled to the right, camera elevated ~30 degrees
- Top-down: character oriented facing toward the right side
- Animation frames must preserve this facing direction — never flip or mirror

### Idle Animation
- Idle is generated by AI like all other animations — 4 frames with subtle breathing/sway poses
- Uses the same `generateAnimationRow()` pipeline as other actions

### Background Removal (Chroma Key)
- Detect bg color from image perimeter (mode of quantized edge pixels)
- **Euclidean distance in RGB**: `sqrt((r-bgR)^2 + (g-bgG)^2 + (b-bgB)^2)` with tolerance=55
- **Flood fill from edges ONLY** — the sole removal method. NO defringe, NO cluster analysis
- Flood fill stops when it hits a pixel with distance > tolerance (character outline)
- Character interior pixels are NEVER touched regardless of color
- Black outline in prompt ensures clean boundary between character and background
- Works with green-skinned characters (Shrek, goblins, etc.) because their skin color distance from #00FF00 exceeds tolerance

### Sprite Compiler Frame Extraction
- Primary: column-based gap detection (find transparent/black column gaps)
- Fallback for grid (square image, w < h*1.5): split into 2x2 quadrants
- Fallback for strip (wide image): equal-width horizontal slicing
- After extraction: normalize all frames to same height across all rows
- Bottom-center alignment for all frames in final sprite sheet
- Skip near-black pixels (r+g+b <= 30) during column occupancy scan

### Game Viewport
- Canvas size: 640x480
- Character stands at bottom of canvas (floorY = canvas.height - 10)
- No ground line drawn
- Jump velocity: -550
